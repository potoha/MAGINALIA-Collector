# 保存データの後方互換の規則

Collector は、利用者のブラウザープロファイル内に未送信の引用を保留します。この保留データは、拡張機能の版が上がっても、下がっても（MAGINALIA Desktop を古い版に戻した場合など）、失われたり読めなくなったりしてはいけません。

## 規則

1. **古い版が書いたデータを、新しい版は必ず読めること。** 次の保存先の形式を変えるときは、古い形式の読み取りを残します。
   - IndexedDB `maginalia-collector-outbox`（版 1）: ストア `entries` / `summaries`（キー `requestId`）、`metadata`（キー `key`、`usage` 行）。
   - `chrome.storage.local` のキー `collector.host-profile`（`{ hostName }` のみ。開発・E2E用の上書き）。
   - `chrome.storage.session` の `collector.capture-transfer.` 接頭辞のキーは一時的なデータで、版をまたいで残す対象ではありません。
2. **0.3.0 は 0.2.0 の保存形式を変えていません。** 形式を変える場合は、先にその変更を別の作業として設計し、次を満たします。
   - 古い行を書き換えず（または読み取り可能なまま）、新しい版が古い行を一覧・開く・削除・再送できる。
   - 一つ前の版が新しい版の行を読めない場合は、データを壊したり黙って捨てたりせず、利用者に分かる文言で読めないことを示す。
3. **保留データを自動で削除・変換・再送しない。** 版の更新は保留キューの意味（同じ依頼IDでの冪等な再送、受領確認後にだけ削除）を変えません。
4. **確認はテストで行う。** `tests/storage-compat.test.cjs` は、0.2.0 の形をした行（固定のリテラル）を保存先に直接書き込み、現在のコードで読み・開き・削除できることを確かめます。このテストの固定データは、現在のコードから生成し直さないでください。

## 背景

Collector は拡張機能として Chrome に読み込まれたまま更新されます。拡張機能を Chrome から削除すると、保留中の引用も消えます。そのため、更新や巻き戻しでデータの形が変わって読めなくなる事態を避けることを、版をまたぐ要件としています。
